# 签名维护操作细节

按目标阅读“核对与恢复”及对应维护模式；需要本机签名时再读“macOS 探针”。本文件描述操作约束，不是携带真实凭据的脚本。

## 核对与恢复

1. 核对 Git remote、`gh api user` 的登录和两个仓库的权限；备份仓库必须仍为 private。没有登录、权限、证书或网络响应不等于“没有旧身份”。检查备份分支、相关路径和工作流，避免触发新出现的自动化或覆盖其他内容。
2. 读取当前源码 DER、Environment pin，以及备份路径的公开 CER/`identity.public.json`，核对完整 DER/SHA-256。获取备份时先固定具体 commit，从该提交读取明确文件集；不要在多次请求中混用移动中的分支 HEAD。签名名称 `ReqWS Personal Code Signing` 不是身份 pin。
3. 实际需要私钥时，读取以下文件到脚本内存或仓库外随机临时目录。所有 API 返回和 Base64 解码由脚本处理，仅输出公开状态；API helper 不得自动保存或打印包含内容的请求/响应。

| 文件 | 用途 |
|---|---|
| `reqws-signing.cer`、`reqws-signing-cert.pem` | 同一公开证书的 DER / PEM |
| `reqws-signing.p12`、`.p12-password` | 加密签名身份与 P12 密码 |
| `reqws-signing-key.encrypted.pem`、`.key-password` | 原加密私钥与独立 PEM 密码 |
| `identity.public.json`、`openssl-code-signing.cnf` | 公开身份元数据与生成参数 |

该布局记录已有身份，不要求为了凑齐缺失的文件重新生成证书。缺项先判断是否能从同一已验证身份补导出；无法证明同一身份时停止。

临时目录使用 `mktemp -d`、0700，文件 0600；校验路径类型、owner 和符号链接边界。不要恢复到固定的 `~/.reqws-signing`、Desktop 或 Downloads。恢复材料核对完成后才用于签名或重传；新的真实材料不能依赖一次性的 `/tmp` 旧脚本或下载 ZIP 中未复核的默认行为。

## 同身份维护

1. 确认用户要求的是重传还是改变指定包装密码。无理由时仅核对并复用现有 Secret，不用 `gh secret set` 当作无条件幂等动作。保持原 DER、私钥、pin 和有效期；P12 密码与 PEM 密码分别管理。
2. 验证证书自签、RSA/Code Signing 用途、有效期、DER/PEM 一致，以及加密 PEM 解密后的私钥与证书匹配。可复用源码 `scripts/macos-build-profile.mts` 的 `validateReleaseCertificate` 做公开 DER 检查；它不验证 P12 私钥或远端 Secrets。
3. 用已安装 OpenSSL 3 的绝对路径检查 P12 完整性和所带证书；密码经 file/fd/stdin 传入，捕获输出且不记录原始失败 argv。更改包装密码时用同一私钥和证书重新导出到新文件，密码随机生成于受控脚本内。验证新旧公钥与 DER 不变，且新密码确实能解密新封装。
4. P12 初始采用 AES-256-CBC、SHA-256 MAC、100000 次迭代。导入错误需结合实际阶段定位；不要以空密码、关闭完整性检查或自动 `-legacy` 重试。确需兼容封装时明确原因及授权，保持同一身份并重跑本机探针。
5. 对将要上传的确切 P12 运行下文 macOS 探针。中断重试可复用已验证的固定备份 commit/文件路径、确切 P12 输入一致性、探针平台/工具及成功清理记录；候选字节和相关运行条件未变时无需重新封装或重复探针。仅有相同证书 pin 或笼统 PASS 布尔值不能证明 P12 封装相同，证据不足时补验。输入摘要仅作临时证据，长期关联使用 Git commit/路径。仅改 PEM 包装时可做受影响的加解密/公钥一致性验证，不为无关改动重签或启动应用。
6. 按“备份与切换”写入并验证新备份。仅更新受影响的 Environment Secrets；同身份维护不改公开 DER 或 pin。改变 P12 密码时 P12 和密码必须成对更新。

## 备份与切换

### 私有仓库

- 每次读写前核对 `fredgnr/reqws-secret` 仍私有且具有所需权限。保持非本任务路径和历史，不 force-push、不删旧身份、不把凭据仓库改成公开；Git 历史保留旧密码，包装改密不能撤销已经泄露的私钥。
- 把本轮材料作为同一次提交内的完整集合写入。以读到的 HEAD 为父提交，更新引用采用非强制方式；遇到并发提交停止，重新核对差异，不用 force 覆盖。敏感内容通过进程内 JSON/stdin 提交，禁止工具回显 payload。
- 对新身份候选使用与当前活动身份分开的路径，例如 `reqws-desktop/macos-signing-candidates/<candidate-id>/`。对同身份改密，记录切换前/后的备份 commit；旧 commit 是中断恢复依据。不要只上传 P12 而遗漏对应密码和元数据。
- 从目标 commit 逐文件读回比较，再用远端取回的密码实际解密 P12 和加密 PEM，核对证书/公钥。只列目录、比较文件名或看提交成功不算恢复验证。比对在内存完成，只保留不含秘密的结果和 Git commit，不生成源码 checksum 清单。

### Environment

从完整分页结果核对 `macos-release`：唯一 reviewer `fredgnr`、允许本人审批、无 wait timer、管理员 bypass 关闭、Selected branches and tags 仅 `type=tag,name=v*`。保留更严格或未知规则，报告差异而不降低保护。已有环境不重建；需要修复规则时按本次授权操作。管理员 bypass 的修改使用受支持网页设置并保存、复查，不能依赖未文档化 PUT 字段。

确认无正在使用或等待审批使用该环境的签名/发布 job，切换期间不批准发布。Secret 名称检查用元数据接口；公开 pin 可以读回，Secret 明文不可读回。上传用 `gh secret set ... --repo fredgnr/reqws-desktop --env macos-release` 的 stdin，不能将密码放入 `--body` 或将 Base64 写入 shell 历史。只有身份激活才写 `MAC_SIGNING_CERT_SHA256`。

按阶段保存不含秘密的操作记录：候选身份、备份 commit/路径、已成功写入哪些字段、旧/新公开 pin、探针输入关联、失败点。写入不是事务；部分成功或响应不确定时，能核对的是公开 pin、Secret 名称/时间、阶段记录和签名 job 状态，不能从这些元数据推断 Secret 内容。保持签名消费停止，在既有同候选恢复授权内重传结果未知的字段；若已成功字段的确切候选关联也不能确认，则有理由成对重传同一份已验证 P12 和密码。不能为了核对内容让 CI 打印或回传 Secret。明确写入成功与 CI 实际消费通过是两种结论；恢复方向不清楚、需回退不同身份或扩大范围时再询问用户。

## macOS 探针

使用 macOS 非 root 会话、已安装工具和一次性测试二进制；不安装或启动真实 ReqWS。只读审计不自动触发此阶段。不要伪造 GitHub-hosted/tag 环境变量来绕过 `with-macos-signing` 的发布上下文限制。

保存本次之前的 keychain 搜索列表、该证书已有用户信任及精确临时路径。创建随机密码的临时 keychain，导入 P12 时仅授权 `/usr/bin/codesign`，不用 `-A`。需要信任时只增加用户级 Code Signing 用途，不设置 TLS/全用途或本机管理员域信任；系统密码和授权弹窗由用户本人处理。

使用 `security find-identity -v -p codesigning <keychain>` 查找明确的 SHA-1 identity，再核对其完整 DER/SHA-256。默认 X.509 policy 可能遗漏只有 Code Signing 信任的身份。不要通过关闭上游检查或扩大信任解决发现失败；ReqWS 的受控构建配置已有额外严格验证。

签署两个不同内容的小型 Mach-O，分别验证自身签名，提取叶证书比对预期 DER。提取 A 的 `designated => ...`，验证 B 满足同一要求，并验证同 Bundle ID 的 ad-hoc 测试文件被拒绝。内联 DR 必须是单个参数 `-R=<表达式>`；独立的 `-R` 后接字符串会被解释为需求文件路径。负向失败必须是签名要求不匹配，不能把参数错误、文件不存在或无法运行当作拒绝成功。

无论成功失败，都清理本次临时 keychain、仅本次新增的信任，恢复搜索列表并读回确认；不移除用户原有信任。记录经过探针的确切 P12 与后续上传输入一致，摘要仅作本地临时证据。探针不等于真实 Electron、Hardened Runtime、Gatekeeper、CI 或自更新验收。

## 身份迁移

重发证书、续签或换私钥都走此路径。先核对是否已有旧身份签署并分发的版本；未知不能按“从未分发”处理。

- 用户明确要求轮换/续签时，可以准备新候选和隔离备份。已有身份仍保留；不覆盖活动备份路径、源码 DER、Secrets 或 pin。首次初始化 profile 为 RSA 4096、SHA-256、3650 天，自签名根直接代码签名，`CA:TRUE,pathlen:0`、Digital Signature/Certificate Sign、仅 Code Signing EKU；有意改变这些参数属于设计变更，不为满足模板改写旧身份。
- 检查候选身份和旧应用的实际 DR。旧版拒绝新身份是预期迁移障碍，不能改成仅 Bundle ID/CN 或任意自签名证书。设计尚无自动轮换桥接；准备新身份版本的可信手动 bootstrap 和后续两版本验收方案。
- 在用户已明确授权激活的范围内，提交可评审的候选、迁移/回退步骤及受影响的发布门禁，再切换活动备份、公开 DER、两个 Secrets 和 pin。若授权只覆盖生成/验证候选，则到此交接，不提前激活。保持切换前的源码状态及备份 commit 可恢复；未确认旧客户端迁移前不宣称更新连续。
- 签名、发布、真实 App 替换分别按具体任务范围执行；新身份准备成功不自动授权这些动作。已分发版本的手动 bootstrap、U5/U6/U7/U9 验收仍需真实候选证据。
- 私钥泄露时报告并按授权停止受影响签名/发布、制定新身份恢复；改 P12 密码、删 Secret 或删除仓库最新文件不能使已有私钥副本失效。不为清除旧秘密擅自重写远端历史。

## 清理与失败交接

成功恢复/备份后，删除本次临时私钥、P12、密码、证书副本和临时 clone（若实际创建）；只保留源码公开 DER及不含秘密的证据。没有备份验证就不要删除唯一的新身份材料；明确报告该例外的精确位置和缺口，等待恢复决定。清理失败不写“已完成”，不得保留 Desktop、固定 home 目录或技能目录中的秘密副本作为默认备份。

日常配置成功结论止于本机验证、远端配置/恢复和清理；真实 CI 尚未消费就明确标为待验证。跟进文档使用主入口链接的项目文档技能，避免将旧报告重新包装成新候选验收。
