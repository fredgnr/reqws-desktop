# 文档改进本地 Agent 交接

继续完成 `docs/readme-user-guides` 分支的真实截图、中文复核和阅读验收。现有正文已重整，不需要另起一套方案，也不要为配合文档修改产品行为。

## 接手前确认范围

先读仓库 [AGENTS.md](../../../AGENTS.md)、[中文写作规范](../../standards/chinese-writing.md)和[素材清单](visual-assets.md)。代码基线与事实修正见[本轮记录](README.md)。

在现有分支继续工作，保留其他人的改动，不因整理文档执行 reset、stash、clean、force-push 或修改 main。当前任务不授权合并、打 tag、发布软件、创建远端测试仓库、改证书/密钥、安装或重启日常 IDE。

拍摄安装、信任或重启过程需要相应授权。GoLand 安装仍通过 manual-only 的 `$reqws-goland-plugin-install` 确认具体产物与目标。缺少环境或权限时，完成独立的文档工作，把对应图片记为待拍，不能用原型冒充。

## 可以怎样拆任务

| 任务 | 输入 | 交付 | 依赖 |
|---|---|---|---|
| D1：Desktop 操作与截图 | Desktop 指南、素材清单、获准的测试工作区。 | 添加仓库、创建、就绪、管理和设置等图片，逐步核对按钮和结果。 | 可用的 macOS App 与 Git 测试数据。 |
| D2：GoLand 操作与截图 | 插件指南、同一工作区、确切插件版本。 | 安装入口、选择与 Project 结果、切换、Git 根目录和诊断图片。 | 插件已按授权安装，目标 build 匹配。 |
| D3：中文与事实复核 | 新首页、指南、规范和下方未处理长文。 | 句子修改、术语核对、事实差异清单；不改历史结论。 | 可与素材整理并行；涉及新事实时查源码或发布记录。 |
| D4：整合与验收 | D1–D3 结果。 | 嵌图、alt、图注、资产索引、链接检查和阅读验收结果。 | 所有 P0 图真实可用；缺项明确保留。 |

可以让不同 subagent 分别复核文字、源码依据和素材清单，但必须遵守仓库的模型及权限要求；无法满足时不要假称已做独立复核。同一 App/GoLand 实例的拍摄串行进行，避免互相改动选择。README 和索引由主 Agent 统一整合，避免并行覆盖。

## 先走通这一条使用路径

使用获准的三个普通 Git 仓库，UI 名称为 `api`、`web`、`shared`。它们不需要 Go 代码；普通文本足以确认目录和文件是否可见。

1. 只看 README，说明 ReqWS 解决什么问题，Desktop 和插件分别负责什么。
2. 按安装页区分 App ZIP、插件 ZIP、源码和更新元数据，不要求安装成品的用户配置构建 JDK。
3. 添加仓库并创建 `checkout-flow`。核对两个目录字段的含义、分支和“就绪”结果。
4. 用已安装的 VS Code/Cursor 打开工作区，核对文件入口；没有该编辑器时明确未验证，不写通过。
5. 在 Desktop 只选 `api`、`shared`，保存并打开 GoLand。信任后在普通 Project 面板展开各仓库的 `docs/overview.txt`，同时查看 ReqWS 状态。
6. 改成 `api`、`web`，保存并确认项目视图更新；核对 `shared` 仍在磁盘上、仍是需求成员，`.code-workspace` 的成员范围没有跟着缩小。
7. 区分取消加载、移除成员和移除记录。使用一次性测试数据确认操作说明，不删除或改动真实用户工作区。

GoLand 文件可见性不要通过 Find in Files、搜索命中数、终端列目录或符号索引证明。打开、关闭项目和同步过程发现真实错误时，记录问题，不删 `.idea` 或所有权文件“让截图好看”。不重复 Go SDK、go.mod、运行调试或 IDE 原生 Git 的完整验收。

## 检查和验收

本轮远端编辑环境没有完整 checkout，未运行仓库级文档检查。接手后，先在完整仓库运行，再在最终嵌图版本运行：

```bash
npm run docs:check
git diff --check
```

文档检查脚本使用 Node 内置模块，但项目仍按 Node.js 24 使用。纯文档工作不需要为了检查而打包、安装 App 或运行全量 Gradle；不要改 CI 来跳过既有检查。

另行检查章节锚点、旧安装入口、相对图片路径和图注。`docs:check` 不验证章节锚点，也不判断文字是否易懂。素材新增后，确认每层目录有 README，实际图片已进入索引；尚未拍摄的文件不得出现在图片链接中。

首次阅读验收应由没有参与这次文案编写的人完成。可以让对方只看 README，再回答：软件帮我省掉哪几步？是否会动原有 clone？Desktop 和插件分别要安装什么？在哪里选仓库、在哪里确认生效？取消加载、移除成员和删除文件有什么不同？Git Log 是否随加载选择变化？

接着让对方按指南找到入口、创建工作区并在 IDE 中确认结果。记录卡住的位置和实际问题，不用“读起来不错”代替过程。无法做真人阅读时，写明只完成 Agent 复核。

## 交付时写清楚

记录实际修改的文件、已完成和未完成的素材 ID、图片来源版本、执行过的检查及结果，以及尚未验证的系统行为。截图来源放在资产索引；测试命令和包校验输出保留在日志或对应证据位置，不提交逐文件源码摘要清单。

完成标准是读者能顺着文档使用软件，而不是所有待办都被勾选。未获授权的安装、缺失的更新环境或未拍图片继续保留真实状态。不要把图片交付写成新的发布 GO，也不要将本轮文档工作合入 main 或发布版本。
