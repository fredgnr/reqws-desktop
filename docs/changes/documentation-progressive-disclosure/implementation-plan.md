# 文档调整的分阶段实施计划

本计划给后续实现者明确的文件范围、依赖、交接与退出条件。此次交付的是计划文件，不是下列迁移已经完成的记录。

## 概述

先接受事实归属和状态解释，再做两个高价值领域试点；确认不会漏规则后才接入读取工具与硬检查，最后滚动迁移其他领域。保持一个集成分支即可，不按任务编号强制拆很多 PR；本次方案 PR 与后续实现 PR 分开表达范围。

## 阶段与依赖

```text
P0 固定基线、审计与方案评审
  → P1 事实归属/状态/模板规范
  → P2 IDE 与发布两个试点，迁出当前契约
  → P3 元数据检索、章节读取和执行检查
  → P4 其余领域滚动迁移、同一最终候选验收
```

P0 的全文阅读和本方案已完成；P1–P4 均待实施。当前字段、CLI 和目标目录不得在交付说明中提前写成已提供。P2 完成前不全局过滤历史/未分类页面；P3 必须复用 P2 的真实导航任务和已发现失效锚点作为测试样例。

## 文件和资源所有权

主 Agent 独占根 `AGENTS.md`、总索引、文档规范、协作规范、package/lockfile、通用 parser/检查入口和共享模板。必须修改锁文件时先说明依赖必要性；不要为格式调整顺便升级工具链。

领域作者可以在 P1 约定后分别拥有 IDE 契约、发布操作、Desktop/设置、测试文档，写入清单缩小到当次实际文件。两个作者不能同时改同一旧大文档：先由指定所有者拆出明确章节，再分配目的页。共享目录 README 的集成编辑由主 Agent 统一处理。

`docs/reference/**` 为禁止写入范围。历史报告允许的变动限于有依据的范围提示、移动时的入链修复和明确附录；不能改写原执行结果、候选、失败或豁免。读取私库与生产凭据不属于任何子任务。

## 子代理策略

不是每个任务都需要子代理。P0 可由主 Agent 串行完整阅读；P2 的只读领域核对可并行；只有 owner 和章节边界明确后才开放有实际收益的并行写入。P3 工具/检查属于编码工作，按[现有 Agent 指南](../../guides/agent-workflow.md)的有效模型与 reasoning 规则选择预设；迁移到新协作标准前仍以现有第 8 节为准，不在本计划复制模型名称白名单。

拟议角色是只读 Explorer（核对现有规则和漏项）、有界 Writer（只写指定文档）、工具 Worker（只写工具与测试）、只读 Reviewer（检查候选范围和规则损失）。角色数量按任务规模裁减；无子代理工具时主 Agent 串行完成并明确没有独立审查。本次没有启动子代理。

委派只给任务所需上下文，不附整库正文：

```text
基线：精确 commit；未提交差异及禁止覆盖范围
目标：要迁移的事实类别及任务验收
必读：适用 AGENTS、规范 owner、来源章节、源码/测试入口
写入：独占的实际文件列表；共享入口由谁整合
保留：不得丢失的安全/兼容/证据条件
验证：只运行该范围必要检查；没有执行就标 not-run
返回：迁移对照、差异、实际检查、剩余歧义；不提交/推送
```

Reviewer 读同一冻结候选，只指出问题，不自行改写事实或放宽条件。文档中既有“曾由独立 Reviewer 通过”不能当成本次 Reviewer 已执行。

## 每个迁移单元的操作顺序

先冻结来源章节并记录其职责、状态和适用版本；再读取当前实现/测试，判定当前事实、提案和证据。先写完整新 owner，再用链接替换旧页的当前事实副本，保留决策理由或历史正文的时间范围。入链、局部索引和替代提示在同一提交修正。

在明确差异没有丢失后，执行有关文档/工具检查及至少一个对应任务路由用例。用旧路径、旧锚点、特殊规则关键词检查残留引用，范围覆盖根 README/AGENTS、docs、相关 Skills 和集成入口。不要递归扫描依赖、build、缓存或私有报告。

代码行为与文档说法不一致时不要靠改文案掩盖；记录为独立待裁决事项。纯文档迁移不顺手修产品，也不将历史失败更改为通过。每阶段可以独立审阅和撤回，不要求目录结构一次搬完。

## 发布与回退边界

本次授权允许文档分支和 PR，不包括合并、tag、Release、凭据配置、真实安装或删除用户数据。远端写入前读取 main 和目标分支；有并发变动先整合，不 force-push 覆盖未知提交。PR 说明区分审计基线、实际提交范围和未运行检查。

迁移回退通过正常 Git revert；不回退产品或远端配置。工具失败时保留普通 Markdown 和精确路径阅读，并明确未完成自动检索，不悄悄返回空规则。历史过滤未满足前提时关闭该过滤而不是隐藏可能仍有效的唯一约束。
