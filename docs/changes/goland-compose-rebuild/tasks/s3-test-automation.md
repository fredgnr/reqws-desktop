# S3：接通独立测试和真实 IDE 验证

本阶段让新界面的常规回归自动运行，同时证明实际 ZIP 在 IDE 中能够接收输入并正确联动项目模型。

## 输入和所有权

G2 已通过，G0 的独立 JBR/图形环境与 Driver 技术路线已验证。Worker A 独占独立 Compose 测试文件和覆盖迁移清单；Worker B 独占指定的本机集成场景/测试侧定位器。Main 独占 Gradle、检查脚本、CI 接线、descriptor 和产物检查。

两者可并行写入但运行产物目录隔离；完整 IDE 进程对 sandbox/显示会话使用单一所有权。不得更改真实用户配置、复制个人登录或向 CI 增加 IDE 授权凭据。

## 子任务

| ID | 内容 | 输出与直接验证 |
|---|---|---|
| S3.1 | 完成独立 Compose 测试集，迁移旧 Swing 的有效行为断言。 | V04–V09 覆盖映射；失败样例、非零发现和报告。 |
| S3.2 | 扩充本机 Driver：真实点击、主题/焦点、内容重建/启用、未打开面板同步及 Project 树。 | 候选 ZIP 的 V03/V06/V09/V10；包含 `2 → 1 → 0 → 2` 和冷启动恢复。 |
| S3.3 | Main 接入独立 CI 任务与产物隔离检查，保留平台/API 门禁。 | 已验证的 `composeUiTest` 或最终命名入口；负例正确失败，测试运行时不进 ZIP。 |
| S3.4 | 汇总 exact-head 证据，补必要的系统可访问性/缩放检查并审查覆盖缺口。 | G3 记录；CI、本机与系统结果分开，剩余必需项不静默移除。 |

## G3 通过条件

新组件测试在声明的环境中运行非零用例，失败能够阻止通过；真实 IDE 中能操作 Compose 控件并观察副作用，不以 direct service call 代替点击；Project 树、配置刷新、恢复与安全边界保持。

CI 继续不启动完整 GoLand；JBR/渲染环境能力不足时相应任务 blocked，不通过清空 CI 标志绕过限制。真正无法自动化的系统检查采取最小必要人工验收并标明环境，不能以“减少 Computer Use”为由省去必需证据。

## 交接

提供 CI/本机命令、实际测试选择器和报告、旧新覆盖对照、待 S4 删除的旧 UI/测试精确清单。普通代码与 API 回归已有结果不等于最终清理候选通过；S4 仍须对清理后的 head 重跑受影响检查。
