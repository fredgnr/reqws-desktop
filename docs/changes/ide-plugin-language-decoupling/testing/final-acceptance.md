# V：最终系统回归与验收

本阶段在 S1、S2 完成后的同一最终候选上统一执行完整插件回归、原兼容矩阵和必要真实 IDE 集成，不重复扩大到语言工具链验收。

## 1. 状态与进入条件

计划状态为 active；本阶段尚未执行，不是第三个开发子任务。只有[S1](../tasks/s1-core-sync-decoupling.md)和[S2](../tasks/s2-scheduling-dependency-cleanup.md)的实际实现、编译和各自必要回归完成，清理清单无已知缺陷后才进入本阶段。

接收两阶段的实际基线/差异、选择器与结果、保留的通用事件处理理由、依赖装配结论，以及是否修改 roots 订阅/关闭恢复路径。先固定用于验证的源码、构建配置与功能输入；完整检查失败后的修复会形成新候选，不能继续沿用旧候选结论。

总契约见[技术方案](../technical-design.md)，共享 T-01～T-07、fixture 与证据规则见[总测试方案](test-plan.md)。本文件是最终执行步骤和 GUI 清单的唯一维护位置，不要求回到两个开发任务再各跑一次阶段集合。

## 2. 最终自动化与装配

在完整仓库、已批准的现有工具链环境中执行：

```bash
# 仓库根目录；本阶段不传 --tests 局部过滤器。
npm run check:goland
npm run docs:check
git diff --check

# 仅在准备所需真实 GUI 候选时打包；不自动安装。
npm run package:goland
```

`check:goland` 应按仓库的现有入口覆盖清理后的完整插件测试、生产符号门禁、配置/结构验证及原 GoLand 2026.1.3/2026.2 Verifier 矩阵。实施时核对实际脚本/任务，不通过删掉任务或保留测试过滤器缩减它；S2 改过依赖时尤其要使用最终配置。

| 最终检查 | 必须覆盖 | 不要求另建重复套件 |
|---|---|---|
| 完整插件自动化 | T-01～T-06，包括新增语言无关回归、保留的 manifest/路径/ownership/VCS 只读/事件/取消/恢复/UI 等自有契约。 | S1/S2 局部集合已包含在完整套件时，无需再各跑一遍。 |
| 构建和兼容 | 原符号门禁、descriptor、实际依赖、配置/结构和原 Verifier 矩阵；打包时校验实际 ID/版本及 ZIP。 | 不重复下载 IDE，不为每个 GUI 动作再扫一次 source/JAR。 |
| 文档与差异 | 当前说明符合已实现行为；删除文件无失效入链；历史结论未伪造、明细可由 Git 历史追溯；源码哈希清单与过程摘要不入库，生成物不入变更。 | 文档修订不机械触发用户项目测试或完整 Desktop 本地测试。 |
| 必要 Desktop/shared 回归 | 只在实际改到启动、共享契约或 Desktop 路径时增加对应本地检查。 | 没改这些层，不增加 Desktop 全业务人工矩阵；现有 CI 正常运行。 |

完整回归不是把阶段结果求和。使用原有增量构建和缓存时，结果必须可追溯到相同有效输入、无局部过滤的完整测试集合；只看到 UP-TO-DATE、局部 XML、历史 GO 或另一候选结果都不够。不能证明覆盖时只重执行所需任务，避免清空依赖或 IDE cache。

确认 test 结果实际覆盖完整保留集合，并区分失败、跳过与未执行。发现有效用例被 S1/S2 意外删除或禁用时，先恢复覆盖再判断，不用总测试数减少本身证明质量改善或回归。

## 3. GUI 准备与身份绑定

使用隔离 fixture 和一个主验证版本的真实 GoLand，记录源码 commit/实际差异、插件版本、构建或 CI run/产物入口、实际加载工件、IDE exact build、macOS/架构和必要 JDK 信息。不要仅凭 ZIP 文件名证明加载了新工件。需要比较安装内容时可临时校验，日志放测试输出，不把具体哈希回写报告；无需源码逐文件清单。

安装/重启真实 IDE 或操作真实用户目录仍需要对应授权；未经授权不能让脚本替用户关闭 IDE。缺少权限或环境记录 BLOCKED/NOT RUN，不从 buildPlugin 或 runIde 推导真实 GUI 通过。

fixture 为 repo-a/repo-b active、repo-c retained、notes 普通目录；仅普通文本 Git 仓库，不要求 Go SDK/Modules、外网仓库或账号。用已有测试辅助层生成合规 manifest 或本地 remote fixture，不扩大 Desktop 生产 URL 策略；详细数据见[总测试方案第 2 节](test-plan.md#2-最小-fixture)。

## 4. 最小真实 IDE 操作链（T-07）

| 步骤 | 操作 | 必须观察的 ReqWS 结果 |
|---|---|---|
| V-G1 打开 | 打开有效 workspace。 | Tool Window 可用；a/b 属于活动集合，c 不属于；受管目录范围正确。 |
| V-G2 添加 | 添加 repo-c；等待正常自动刷新。 | c 进入活动集合及应有项目范围，不依赖手动 Sync Now 修复。 |
| V-G3 逻辑移除 | 逻辑移除 repo-b；等待自动刷新。 | b 退出活动集合并按受管策略排除；磁盘数据仍保留，notes/非 owned 条目不被误改。 |
| V-G4 重加 | 重新加入 repo-b；等待自动刷新。 | b 恢复到应有目录范围，状态与当前 manifest 一致，无持续同步循环。 |
| V-G5 手动重读 | 自动链完成后单独点一次 Sync Now。 | 幂等、正确重读，不误报新的 Go 错误，不覆盖用户配置。 |

允许通过真实 Desktop 的已有测试入口改变成员，或者由测试辅助层模拟 Desktop 的有效原子 manifest 替换；报告必须明确区分“Desktop→插件 E2E”和“manifest 边界集成”。使用辅助层不能写成 Desktop 创建/启动已验证；未修改 Desktop 时不为本次清理再强制完整业务 E2E。

自动链每步先观察自动结果，不能提前点击 Sync Now 掩盖自动刷新故障。目录范围的精确 Workspace Model/PFI 断言由自动化覆盖，GUI 补真实用户路径；必要时用普通文本搜索辅助，不要求每步重新读取语言 registry、扫描代码引用、比对全部 IDE 配置或追踪完整进程树。

## 5. 只有实际影响时才增加的集成

| 实际影响 | 最终阶段增加一次 | 没有该影响时 |
|---|---|---|
| S2 或连带 S1 修改 roots 订阅、关闭/恢复路径 | 同一候选关闭重开一次，核对集合、范围与恢复，不重新执行全部 GUI 链。 | 不为阶段数量重复重启/安装。 |
| 修改的 API 或已知缺陷存在 IDE 版本差异 | 在另一个版本验证该特定风险。 | 主版本 GUI + 原有双版本 Verifier 足够，不加双版本全 GUI 矩阵。 |
| 布局、交互或可访问性实际改变 | 相关截图、键盘或无障碍检查。 | 不重复未改主题/布局/VoiceOver 全套。 |
| 明确的事件/资源/规模风险或具体故障 | 有界追踪或规模用例，写清假设和观测区间。 | 不默认增加 50+20、sleep/wake、多轮长 idle 或全进程取证。 |

## 6. 非目标、失败与缺口

不执行用户项目 `go test`、Go run/debug、补全/跳转/引用、Go Modules registry、GOROOT/GOPATH/SDK/依赖矩阵，也不测试原生 Git diff/log/commit 的全面正确性。逻辑移除不要求保留仓库的运行配置无法运行；重新加入不保证语言配置立即恢复。

删除旧补偿可能重新暴露 Go registry/运行配置滞后，记录这一行为差异，但不把语言未就绪本身作为 ReqWS 失败。若能够证明插件违反通用平台契约，仍应修复对应缺陷；活动目录仍被错误排除、范围/PFI 不一致却显示成功、越权写入、用户配置破坏、自动刷新/恢复/取消回归或事件循环，均阻塞验收。

必需自动化、装配或兼容检查失败即 FAIL；缺少所需 GUI/环境证据不能写完整功能 GO。允许分别报告“自动化通过、GUI 未运行/阻塞”，但 BLOCKED、NOT RUN、OUT OF SCOPE 都不能算 PASS。

## 7. 结果与缺陷修复后的重跑

只在实际执行后新增按次报告并更新测试索引，记录候选身份、T-01～T-07 的真实结果/证据位置、完整套件执行/失败/跳过数、原兼容矩阵结果、工件绑定、GUI 集成类别、条件扩展与未执行理由。沿用一个最终报告即可，不需要把 S1/S2 再各复制成正式报告。

V 发现缺陷时先补或运行直接失败回归，再在修复后的候选上重新建立所需完整插件/兼容证据；运行逻辑、依赖、构建或 GUI 工件改变，就重做相关集成。只有文档改动且功能输入/工件确实未变时可复用对应功能结果，但必须说明绑定关系。

最终通过不自动授权合并、tag、发布或安装到真实工作区。本文件目前只是计划，没有执行记录；旧 verification 不作为本次候选结果。报告使用 Git/CI/工件引用而非具体摘要表；Wrapper 的固定版本与无 distribution checksum 配置按既定规范保持，不在验收时重新生成清单。
