# GoLand 工作加载集合需求与边界

本需求允许在不改变需求成员和磁盘仓库的前提下，选择当前 GoLand Project 加载的仓库。

## 1. 已知问题与目标

当前策略把整个 workspace 作为内容根，再排除部分目录。两轮用户验证支持改为专用 IDE 入口和动态仓库内容根，但单独移除入口 Content Root 不足以消除入口节点；候选实现还需要精确入口排除与 Project 树过滤。来源及限定见[验证依据](verification-basis.md)。

目标为一个 GoLand Project、一个 ReqWS 创建的承载 module 和多个可选择的仓库 Content Roots。它不是三个独立 Project，不合并各仓库的 `.idea`，也不承诺独立的项目级 SDK、运行或插件配置。

### 1.1 最新范围决定：直接替换，不做兼容

用户明确允许历史代码/逻辑直接清除。本需求不维护旧 Desktop/插件/GoLand、旧 schema/ownership 状态、原目录模式或迁移/降级路径；本版唯一目标为 `GO-262.9437.286`。删除旧模式专用代码、测试、文案和构建矩阵，不为旧行为保留隐藏开关。

取消兼容不等于删除用户数据或取消当前正确性。仓库目录、用户 `.idea`、用户额外 root、路径安全、原子写入、当前状态冷恢复仍需保护。本轮只更新方案，实际清理由实施任务完成。

## 2. 业务集合

`M` 是 `.reqws/workspace.json` 的需求成员集合；`L` 是本 GoLand 入口请求加载的成员集合；`U` 是用户在 IDE 显式添加的非受管内容。三个集合不能混为一谈。

| 操作/模式 | 业务行为 |
|---|---|
| 默认全部 `all` | `L = M`；以后新增需求成员也随之请求加载。 |
| 指定集合 `selected` | `L = selectedRepositoryIds ∩ M`，采用 manifest 顺序；新成员不自动选中。 |
| 显式空集合 | `selected + []` 表示不加载任何 ReqWS 仓库，不能回填全部。 |
| 暂不加载 | 从受管 IDE 内容范围退出；不删目录、不切分支、不改需求成员或 VS Code/Cursor 工作区。 |
| 从需求移除 | 沿用 Desktop 已有成员操作，属于不同业务；磁盘保留规则不改变。 |
| 重新加载 | 使用原位置，不重新 clone 或复制。 |

选择文件保留显式 ID 意图。成员移除不强制重写选择文件；暂时不属于 `M` 的 ID 不生效，同一 ID 重新加入需求时恢复原选择。Desktop 保存新选择时只接受当前成员 ID，并清理这次提交中已失效的旧 ID。该规则避免双文件事务，UI 必须说明，不能隐式将未知 ID 解释成全部。

## 3. 用户可见行为

工作区详情新增“GoLand 工作加载”区域，包含模式、仓库勾选、已选择数量和保存/保存并打开动作。非 ready workspace 不可准备入口或保存；保存成功只表示配置落盘，不能表示 IDE 已同步。GoLand 按钮始终使用专用入口，首次打开前自动准备本版绑定和初始选择；不提供“启用新模式”“按原目录打开”或回退按钮。原 `.idea` 不读取/迁移，也不自动删除。

普通 Project 面板显示加载仓库及用户额外内容，允许平台保留 module 容器、Libraries 和 Scratches。正常已同步状态下，不展示可展开的 ReqWS shell 或其内部文件；Excluded Files 开、关两态都成立。标题/提示中的完整路径不等于代码目录节点。初始化和 Safe Mode 不承诺零帧闪现或零后台 IDE 活动。

插件面板按成员展示“已加载”“未加载”“目录缺失”“仍被其他项目根包含”等状态；不将“未加载”当成需求移除或同步失败。插件不提供第二套选择写入操作。

## 4. 用户配置保护

默认采用保留 `U` 的政策，不做严格排他的 IDE 项目。`U` 可以继续可见并参与 IDE 功能；受管空集合不等于整个 Project 空白。

仅凭 module 由 ReqWS 创建，不能清空其中所有 roots。非受管 root、SDK、library、source/exclude 配置、VCS mappings 均保持。拟删除的受管 root 如果已经包含无法安全保留的用户子配置，停止该条删除并报告冲突，不通过级联删除抹掉配置。

用户的额外 root 若覆盖已取消加载的仓库，保留它，提示“已退出 ReqWS 加载集合，但仍被其他项目根包含”。不得报告该仓库已经完全退出 IDE 内容范围。

## 5. 职责与非目标

Desktop 唯一写入成员 manifest、GoLand 绑定/选择，负责仓库生命周期和 IDE 启动；插件只读业务配置，受信任后管理可证明归属的 IDE 条目。保持语言无关、路径/目录身份检查、原子持久化、取消和用户配置保护。

本轮不实现多 Project/一仓一 module、Go 专属逻辑、命名工作集、双向 RPC、插件自动安装或更新、`.idea` 自动迁移、Git Log/Commit 自动过滤、VCS mapping 写入、目录搬迁或新平台支持。既有自更新/签名流程不改动；新增 Desktop 写操作应纳入现有活动门禁。

## 6. 完成条件

完成[技术方案](technical-design.md)和[测试计划](test-plan.md)要求的真实控制链、冷启动、空集合、用户额外 root、绑定和所有权保护，并完成旧代码/专用测试清理和单目标构建验证；不存在 legacy 分支或旧版本矩阵。已有 GO FOR IMPLEMENTATION 不能替代它们。

GUI 判断文件/文件夹是否可见，必须在普通 GoLand Project 面板展开具体目录查看节点。禁止以 Find in Files、Find in Path、Search Everywhere 或结果数量代替。磁盘是否保留可由限定夹具的文件系统断言证明；项目范围语义由自动化模型/PFI 检查证明，两者都不能冒充 GUI 证据。
