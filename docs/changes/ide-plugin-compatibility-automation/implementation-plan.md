# IDE 插件兼容性与自动化回归实施与验收

本文把改造拆成可验证的任务，并规定何时可以用自动化证据替代旧的 computer use 回归要求。

政策和技术取舍以[改造方案](technical-design.md)为准；开发落点与未执行项见[开发记录](implementation-2026-09-21.md)。L0/L1/L4 继续在 CI，只有完整 IDE 的 L2/L3 移到本机。授权准备另用专用测试 profile 供用户交互登录，业务 fixture 每轮隔离。后续授权执行的测试结果见[验证记录](verification-2026-09-21.md)；本机启动后发现的宿主/fixture 修复和实际场景结果另见[本机回归记录](local-verification-2026-09-22.md)，账号复用和未执行的故障注入继续单独记录。

## 1. 实施顺序和协作

按 `S1 → S2 → S3 → V` 推进，不为阶段编号强制拆多个 PR。S1 固定配置、候选 ZIP 和报告接口后，S2 的测试实现与 S3 的 CI 接线可以在不冲突的文件范围内并行；最终由主 agent 集成。

| 任务 | 负责内容 | 完成条件 |
|---|---|---|
| S1 兼容范围与 API 检查 | 统一版本配置、最低 SDK 迁移、descriptor、目标解析、Verifier、缓存适配。 | 262 最低版本验证完成；候选无上限；自动 API 目标和失败处理可复现。 |
| S2 本机固定环境自动集成 | 保留平台覆盖和 Starter/Driver 三组用例，增加独立授权准备、profile 复用与运行报告。 | 本机自动运行并能检测反例；缺授权/图形/权限明确阻塞，未运行不得通过。 |
| S3 工作流与规范迁移 | CI 只保留编译、L0/L1、结构/产物策略和 L4，修正 CI/Release 证据范围。 | 无工作流启动完整 IDE或要求 IDE 授权；本机状态独立，CI 绿色不等于 UI 通过。 |
| V 独立验收 | 针对最终提交复核产物、测试、门禁与范围声明。 | 下表要求有真实证据，没有把未运行/阻塞写成通过。 |

可安排只读 subagent 分别审查兼容语法/API、测试反例和 CI 安全；编码 subagent 的路径所有权应分开。`build.gradle.kts`、统一策略文件和 CI 汇总由主 agent 合并，避免多代理各自改版本或重写入口。使用前确认任务指定的模型与权限，不能假称已经运行不具备的 subagent。

## 2. S1：版本政策、产物和 API

### 实施内容

1. 从官方目录及真实分发包确认 GO 262 最早正式版，固定编译 SDK，核对 JBR、字节码与 Kotlin 依赖。当前 2026.2.1.1 保留为固定 GUI 代表环境，不再作为兼容下限。
2. 新增统一配置，显式生成 `since-build="262"` 并取消两个 upper 属性。增加最终 ZIP 检查，不只 grep Gradle 源文件。
3. 将本地 SDK 验证改为结构化 ProductInfo 校验。区分编译 override 与测试目标，错误产品、错误发行版或缺失信息必须报错；任何 override 都不能改变产物最低系列。
4. 构建固定版本解析器，先输出运行快照，再驱动 Verifier；报告适配器明确区分兼容失败、环境阻塞、缺失结果与通过。
5. 更新缓存读取器和对应工作流测试，移除“编译与验证只有同一版本字面量”的假设，保留默认分支共享缓存写权限。
6. 通过已有 release staging 路径向下游交付同一 ZIP；签名、版本校验和发布授权不变。

### 必须覆盖的反例

| 编号 | 测试输入 | 应有结果 |
|---|---|---|
| C1 | 最终 ZIP 下限是 `262.*`、精确补丁 build 或未经批准的更高系列。 | 策略检查失败，不能发布。 |
| C2 | 源或打包 descriptor 残留普通/strict 上限。 | 检查失败；不得只检查其中一个。 |
| C3 | 本机 SDK 升到后续系列或切到 IDEA。 | 不影响产物政策；角色校验失败，不静默升级 SDK。 |
| C4 | 发行目录包含重复项、EAP、跨产品版本、`2026.2.9` 与 `2026.2.10`。 | 正式目标分流正确、数值排序、产品/build 去重正确。 |
| C5 | 官方目录不可用、空矩阵、必需版本无法下载，或验证工具未产生报告。 | 阻塞/未完成，绝不回退成绿灯。 |
| C6 | 人工引入对最低 SDK 不存在的生产 API，或让目标报告包含真实缺类/缺方法。 | 编译或 API 门禁失败。工具链可使用专用负向 fixture，不修改正式生产逻辑来制造假结果。 |
| C7 | 一个新版本 API 失败，其余通过。 | 汇总失败，保留目标结果；不删除失败目标、不自动提高下限或写入上限。 |
| C8 | 版本配置从一个 IDE 扩展为多个 API 目标。 | 缓存解析及路径测试通过；PR/Release 仍不可写共享 cache。 |

S1 先运行配置/解析器/工作流单测，再完成最低 SDK 的生产与测试编译、完整保留插件测试和当次全部稳定目标的 Verifier。零测试、全跳过、只打出 ZIP 不能算完成。

S1 完成但 S2/S3 尚未交付时，不发布“自动化改造完成”的结论。新 descriptor 可以在实现分支中验证，但最终正式交付必须通过 V。

## 3. S2：仅在本机执行完整 IDE 自动集成

### 先清点，再改测试

对当前手工 case 建一张一次性的迁移映射，记录旧 case、ReqWS 契约、已有 L0/L1 选择器、新增 L2/L3 选择器以及删除/保留原因。映射放在实施记录中，不复制成多个长期维护的清单。

`ManagedRootsAdapterTest` 的 `HeavyPlatformTestCase` 与 `ShellPresentationTest` 等 Light/Heavy 平台覆盖继续在 CI，不能因 Heavy 名称迁出。保留所有权、用户配置、取消、dispose、原子持久化等回归。Starter/Driver 的实际 Project 树、自动刷新、空/非空选择冷启动仍是自动用例，只改变执行地点。

### 最小环境探针

后续验证时先在本机准备专用 profile：`run_local_ide.py prepare --profile ...` 打开固定 GO 2026.2.1.1 的无项目环境，允许用户通过 JetBrains Account 登录并正常退出；可选 License Server，不设硬性前置要求。入口从空目录初始化 profile 并独占锁定，禁止导入/同步日常 IDE 设置；不自动复制任何个人许可或令牌。

`run_local_ide.py run --profile ... --archive ... --version ...` 消费已有 ZIP，不重新构建生产插件；每轮新建 fixture/system/plugins/logs，仅直接复用专用 config 授权状态，旧项目记录隔离到本轮私有目录。实际 IDE ProductInfo、ZIP 摘要、版本、进程结果和 XML 均进入本机报告。图形/权限/授权或启动状态未满足时记环境阻塞；准备会话退出不构成 UI 通过。

探针跑通后实现方案第 6 节三个场景组。使用普通文本本地 Git fixture；允许测试宿主初始化临时 Git 仓库，不允许生产插件因此新增 Git 命令调用。

| 编号 | 反例/变化 | 应有结果 |
|---|---|---|
| I1 | 禁用真实文件事件消费链，仅直接调用刷新仍可得到正确模型。 | 自动同步用例必须失败，证明未绕过监听链路。 |
| I2 | 保留旧 Synced 状态，新 revision 从未应用。 | 等待超时或结果不匹配，不允许通过。 |
| I3 | Project 树仍显示取消加载的 repo 或入口元数据。 | 树路径断言失败；搜索结果不能替代。 |
| I4 | 清空后冷启动丢失选择，或取消加载删除了用户 root。 | 恢复/所有权断言失败；磁盘 fixture 校验仍在。 |
| I5 | IDE 进程异常、卡住、提前退出、错误上报丢失。 | 测试或外部 watchdog 失败，并有日志和必要诊断。 |
| I6 | 测试选择器失效、全部 skipped、报告丢失。 | 集成汇总失败，不以宿主 exit 0 通过。 |
| I7 | 未配置 License Server；专用环境未登录或授权过期。 | 允许交互授权准备；正式自动运行遇授权窗口时环境阻塞，不假定继承日常登录。 |
| I8 | 重复轮次/并发 profile、旧 fixture/system 或签名前 ZIP 报告。 | 独占锁拒绝并发；新轮次不复用业务状态；不同 ZIP 不能借证据。 |

负向证明可以由专用测试插件、fixture 或测试层注入实现，但不能把用于注入的控制接口发布到生产插件。固定环境至少完成多次冷启动重复运行，记录实际次数和失败情况；禁止无限重试直到绿。网络准备失败可有限重试，但需保留原始失败。

## 4. S3：CI、发布与文档接线

### 自动工作流

影响分类器的单测要覆盖文档、插件逻辑、模型/UI、共享契约、入口生成、依赖、构建、删除/重命名，以及分类器自身修改。分类器与聚合检查逻辑变化默认执行全插件检查，不允许通过宣称 docs-only 跳过自身验证。

保留原必需检查名称，CI/PR/Release/定期任务只汇总编译（含 Starter/Driver 宿主）、完整单元与 Light/Heavy 平台、禁用 API、结构/产物策略及冻结 API 集合。删除工作流中的完整 IDE job 和授权变量，不用 `integration: false`/skipped 冒充 UI 通过。API 消费 build artifact；本机使用显式同一 ZIP 单独出报告，正式签名产物不能复用签名前结果。CI 证据必须标明 `scope=ci-api` 与 `localIntegration.status=not-run`。

每周 API 检查是拟新增的 GitHub Actions schedule，不是 ChatGPT 定时任务。本次不创建任何未来执行任务；S3 实现后再验证 schedule/manual 路径。它检查 main 候选及已发布 ZIP，不在后台触发用户机器或复制个人配置。

| 编号 | 失败演练 | 应有结果 |
|---|---|---|
| W1 | API 分片一个失败/取消，或 required 子任务没有执行。 | `GoLand plugin checks` 不得成功。 |
| W2 | 纯文档变化。 | 只要求文档/影响评估；结果记录为有依据的不适用，不假称插件测试通过。现有工作流在 S3 前仍原样运行。 |
| W3 | 修改 descriptor、测试框架或影响分类器。 | 全插件自动门禁，不能被“无 UI 变化”绕过。 |
| W4 | release staging 或签名后替换 ZIP。 | 发布校验绑定最终 artifact，API 结果不能借用另一个 ZIP。 |
| W5 | 最高可用 IDE 更新。 | 只扩展自动 API 集合，不新增真机/GUI job，不移动 GUI 代表版本或最低系列。 |
| W6 | 试图将 floor 升到新系列、排除最低目标或掩盖缺失报告。 | 策略/矩阵/报告检查阻塞；PR 中必须有明确评估，用户批准另行审查。 |
| W7 | PR/Release/定期或可复用工作流包含 Starter 启动、`checkIdeIntegration`、License Server/IDE 授权注入。 | 工作流契约检查拒绝；Heavy 平台测试仍保留。 |
| W8 | CI API 成功、但本机集成未执行或环境阻塞。 | CI 只声明自身范围通过，本机状态仍未运行/阻塞；发布字节只绑定真实 CI API 证据。 |

工作流权限继续最小化。运行不可信 PR 代码的任务不得拿签名、发布或用户凭据；不能通过 `pull_request_target` 执行 PR 代码来获取这些权限。发布同产物检查沿用受保护环境，不扩大授权。

### 同步文档

S3 更新以下现行入口；先区分当前事实与历史证据，不能批量替换所有出现的 build 字符串：

- `AGENTS.md`、IDE 插件开发测试规范和插件 README：取消“唯一精确 build”的长期政策，加入每次最低版本影响评估。
- 开发/验收指南和任务提示词：固定环境自动集成替代对应 computer use；明确最高版本没有 GUI 门禁。
- 当前 CI/Release/Marketplace 方案：描述无上限、API 目标快照、最终产物和实际触发方式。
- 手工安装 skill：保留明确请求、目标工件确认和用户机授权；不能因自动 Starter 测试而隐式激活本机安装。

历史报告继续记录原 build 和当时的真机结果，不作为新候选证据，也不改写成新兼容范围已通过。各文档及最近一级索引同步更新。

## 5. V：最终验收与证据

由非实现视角复核最终提交；可以使用只读 subagent，但不得以模型名字或“独立审阅”字样替代实际检查。

| 验收项 | 必需证据 |
|---|---|
| 兼容声明 | 最终 ZIP 内主 descriptor 为 `since-build="262"`，没有两个上限；插件身份与 GoLand 产品依赖未漂移。 |
| 最低系列可用 | 官方最低 262 正式 SDK 的解析记录、生产/测试编译、保留测试及 API 报告。未证实前不能宣称整个系列可用。 |
| 更高版本策略 | 当次完整正式目标清单、每目标 Verifier 终态；不要求也不伪造高版本 GUI 证据。 |
| 行为回归 | 仅本机固定代表环境三组真实结果及 I1—I8 反例；独立绑定候选 ZIP/实际 IDE，不从 CI 推导。 |
| CI 结果 | 影响分类与 W1—W8；同一候选的自动子任务和汇总一致，不运行完整 IDE、不需要 IDE 授权。 |
| 手工回归缩减 | 迁移映射表说明已覆盖/已删除的重复检查；无默认最高版本或每迭代全量 computer use 清单。 |
| 缓存与权限 | 缓存路径/键/写权限测试，未缓存整套用户态 sandbox；原签名发布权限不扩大。 |
| 文档 | `npm run docs:check` 通过；当前策略、目标配置、命令和实施状态一致，历史报告保持原义。 |

沿用现有 `npm run check:goland` 作为完整候选验证入口，S3 根据实现接入新的策略/API 检查；固定环境集成使用实现后的明确入口。交接必须记录实际可执行命令和选择器，不能只复制本方案的拟议任务名。

2026-09-21 的开发轮次按用户要求不运行测试/回归；开发记录与验收条件分开，不能把未执行项视为通过。

## 6. 退出旧手工门禁的条件

一个旧手工 case 只有在替代自动化于相应地点真实运行、能检测对应失败并保留证据时才移出常规清单；L2/L3 使用本机报告，L0/L1/L4 使用 CI 报告。移除后不重复要求人工逐步证明同一契约，也不增加多版本本机 GUI 矩阵。

自动化环境不可用应记录基础设施阻塞。只有能指出自动化无法覆盖的具体 OS 或用户机问题，才申请有范围的 computer use；不把它作为所有 CI 故障的默认退路，不为最高版本设置例外的例行真机要求。

完成 S1/S2/S3 并通过 V 后，才在交付记录中写“改造已完成”。发布、合并、tag 和真实用户环境操作仍需要各自授权，不由方案 PR 自动授权。
